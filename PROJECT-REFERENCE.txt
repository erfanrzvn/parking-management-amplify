================================================================================
                        🗄️ Database Schema (DynamoDB Tables)
================================================================================

1️⃣ ParkingConfig
   ─────────────
   - id: string (PK)
   - name: string
   - totalSpots: number
   - updatedAt: datetime
   - updatedBy: string

   Authorization:
   ✅ Admin: create, read, update, delete
   ✅ Public: read only

2️⃣ Resident
   ─────────
   - id: string (PK)
   - email: email
   - name: string
   - phone: string
   - building: string
   - floor: string
   - unitNumber: string
   - plate: string
   - userId: string
   - householdId: string (برای گروه‌بندی خانوارها - UNIQUE per household)
   - createdAt: datetime
   - updatedAt: datetime
   - deletedAt: datetime (soft delete)

   ⚠️  IMPORTANT: residentCode حذف شد!
   → هر HOUSEHOLD یک کد مشترک دارد (householdId)
   → نه هر RESIDENT جداگانه!

   Authorization:
   ✅ Owner: read, update own data
   ✅ Admin: full access
   ⚠️  Public: read (مشکل امنیتی! باید حذف بشه)

3️⃣ Reservation
   ───────────
   - id: string (PK)
   - residentId: string
   - householdId: string (کد خانوار - به جای residentCode!)
   - residentFloor: string
   - residentPlate: string
   - guestPlate: string
   - guestMobile: phone
   - guestEmail: email
   - startTime: datetime
   - endTime: datetime
   - status: string (CANCELLED)
   - deletedAt: datetime (soft delete)
   - createdAt: datetime

   ⚠️  تغییر مهم: residentCode → householdId
   → هر reservation به یک household لینک میشه، نه یک resident

   Authorization:
   ✅ Public: full access (برای guest booking)
   ✅ Admin: full access

================================================================================
                        🔧 عملیات CRUD - چطور کار میکنه
================================================================================

CREATE RESIDENT:
1. Frontend: createResident() در graphql.ts
2. AppSync: mutation CreateResident
3. DynamoDB: Insert به جدول Resident
4. Frontend: reload data و نمایش

DELETE RESIDENT (Soft Delete):
1. Frontend: deleteResident() در graphql.ts
2. AppSync: mutation UpdateResident با deletedAt=now
3. DynamoDB: Update رکورد (NOT physically deleted!)
4. Frontend: فیلتر کردن رکوردهای deletedAt != null

CANCEL RESERVATION:
1. Frontend: cancelReservation() در graphql.ts
2. AppSync: mutation UpdateReservation
3. DynamoDB: Update با status='CANCELLED', deletedAt=now
4. Frontend: reload و نمایش

    allow.group('ADMIN'),              → فقط Admin میتونه CRUD کنه
    allow.publicApiKey().to(['read']), → همه میتونن بخونن
  ])

Resident:
  .authorization((allow) => [
    allow.owner(),                     → هر کاربر فقط خودش رو میبینه
    allow.group('ADMIN'),              → Admin همه رو میبینه
    allow.publicApiKey().to(['read']), → ⚠️  همه میتونن لیست ببینن (SECURITY ISSUE!)
  ])

Reservation:
  .authorization((allow) => [
    allow.publicApiKey(),              → همه میتونن رزرو کنن (برای Guest)
    allow.group('ADMIN'),              → Admin کنترل کامل
  ])

   - اگه خانواده جدیده → یک householdId جدید بساز

⚠️  وقتی Guest رزرو میکنه:
   - باید householdId داشته باشه
   - سیستم چک میکنه: آیا این household الان رزرو فعال داره?
   - اگه داره → رد میشه
   - اگه نداره → رزرو میشه
